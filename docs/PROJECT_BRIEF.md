# Immerse Jam：需求与参考应用调查

更新日期：2026-10-28。当前阶段：Windows 0.1.2 已实现并生成安装包；详细进展见 README 与 VALIDATION。

## 已确认的产品要求

- 名称暂定 **Immerse Jam**。界面沿用 Audio Jam 的布局和操作习惯，独立实现应用。
- 先完成 Windows，随后实现 Android；数据格式和核心播放语义从一开始兼顾两端。
- 音轨分离、和弦识别和其他音频分析在本机运行。
- 安装程序提供应用自己的运行环境，不要求用户预装 Python、Node.js、CUDA 工具包等开发环境。GPU 加速需要兼容驱动，并提供 CPU 路径。
- 首次安装允许联网自动下载。电脑端质量优先，可接受约 1–3 GB 的模型；具体是单模型还是默认模型组合的预算仍需在选型时说明。
- 不设置会员、订阅或分离次数限制。侧边栏提供自愿打赏入口，使用用户提供的微信收款码。
- Android 安装后允许选择经过验证的模型，也允许导入受支持的自定义模型。
- 设备互传默认传原曲与分轨，双方可以选择歌曲。局域网或手机热点下扫码配对。
- 远程传输优先设备直连；允许使用免费连接服务，不要求用户自行搭建或付费租用服务器。免费服务的可用性和中转额度需要实测，不能承诺任意网络下必然连通。
- 尽量迁移本机已有 Audio Jam 内容，至少调查原曲、分轨、歌单、练习标记、附件的可迁移性。

## 参考应用的本机事实

- 安装目录：`D:\Audio Jam`。
- 版本：`3.8.6-882`，从程序包的 `package.json` 读取。
- 桌面外壳为 Electron；程序包位于 `resources/app.asar`。
- 程序包包含 alphaTab 1.6.3（包声明 MPL-2.0）和 Superpowered 播放资源。
- 包内没有发现 `.onnx`、`.pth`、`.pt`、`.tflite`、`.ckpt`、`.safetensors` 模型文件。这仅说明该包不自带这些格式的权重，不单独作为云端推理的完整证明。
- 用户配置目录：`C:\Users\hachimi\AppData\Roaming\audio_jam`。歌曲数据库位于 Windows 文档目录的 AumDb/index.db，媒体在 AumDb/assets；已提供只读扫描与复制迁移。
- 调查仅提取版本、依赖、界面行为和声部定义；参考应用实现代码不作为新应用源码。

### 已核对的分离模式

以下来自本机应用的预设声部定义，不能据此断言云端使用了什么模型。

| 模式 | 输出声部 |
| --- | --- |
| 基础模式 | 人声、鼓、贝斯、其他 |
| 完整模式 | 人声、吉他、钢琴、贝斯、鼓、其他 |
| 吉他手模式 | 主奏吉他、节奏吉他、其他 |
| 鼓手模式 | 鼓、其他 |
| 贝斯手模式 | 贝斯、其他 |
| 歌手模式 | 主唱、和声、其他 |

另有自定义声部选择逻辑，需要继续核对可选组合。主奏/节奏吉他和主唱/和声需要专用模型或多阶段处理，六轨模型本身不足以覆盖。

### 播放与练习功能清单

本机界面已看到：波形视图、和弦格子视图、吉他和弦指法、Key/BPM、六轨音量、Mute/Solo、左右声像、AB 循环、段落书签、变速入口、音调入口、乐谱视图入口、混音预设。

结合用户要求及官方资料，需要逐项验收：

- 原曲和多轨播放，共用时间轴；独奏、静音、音量、声像、主音量、EQ。
- 变速不变调、独立移调，和弦显示随调性变化。
- AB 循环、多段标记、定位、按住试听并返回、快捷键。
- 节拍检测、节拍器、倒数进入。
- Guitar Pro 乐谱导入、MusicXML、独立 MIDI 文件导入与同步播放。
- 乐谱/六线谱预览、跟随和高亮；按用户选择 B，自动对齐后允许整体与局部修正。
- 和弦、调性和 BPM 的本地分析及手动修正。
- 本地歌曲库、歌单、附件、导出；官方资料中的视频导入、录制等播放相关能力仍需继续核对。

## 模型接口和故障处理要求

- 每个模型必须有清单：格式、架构/适配器、版本、采样率、输入声道、声部名称、输出轴含义、互补关系、资源需求、校验值和来源。
- 不以轨道数量猜声部含义，不固定假设两轨、四轨或六轨。
- 导入时校验文件和配置，并在独立工作进程中试运行；实际输出数量/维度必须与清单一致。
- 拒绝不支持的架构、重复声部、输出数量不符、无效采样、损坏或不完整模型，并提供明确原因。
- 处理后统一采样率、声道和样本长度，检查无效数值；完成验证后再一次性提交新分轨。
- 不把“原曲”“吉他合轨”和“主奏/节奏吉他”等重叠声部同时默认混入，避免重复叠加。
- 换模型、取消、显存不足或失败时保留此前可播放的项目；使用分块推理控制内存，提供降档和 CPU 回退。
- 运行环境、模型下载和项目导入必须支持中断恢复、完整性检查和失败清理。

## 迁移和互传原则

- 读取现有曲库进行迁移，不修改原应用数据库或原媒体文件。
- 生成迁移预览，区分本机完整文件、缺失文件和只有云端引用的内容。
- 通过稳定歌曲 ID 与内容校验去重；导入失败不能留下半个可见项目。
- 传输前双方确认歌曲清单，默认仅原曲和分轨；附件和练习数据可保留为可选扩展。
- 配对凭证应短期有效，连接只允许访问用户选中的文件。
- 分块校验、断点续传、路径检查和空间预检。
- 局域网功能独立于远程连接服务；暂不把蓝牙作为大文件传输的首选。
