## 已定位的失败

`main` 当时已是 `eddf1b3`，不是代码漏传。旧分支的失败属于各自历史提交，不回写或重跑所有存档分支。

1. [Source checks 41629834836](https://github.com/Kreeli/immerse-jam/actions/runs/41629834836)：类型、格式、单元和构建均通过，失败在 UI 脚本寻找已移除的 MIDI 文案。随后也清除脚本中旧和弦库、独立名称框、BPM 编辑器断言，使用实际播放进度代替固定延时。
2. [Pages 41629834931](https://github.com/Kreeli/immerse-jam/actions/runs/41629834931)：脚本把菜单“跟练”当按钮、仍使用旧新建入口。修正后还发现网页真实布局问题：入口继续加载零散旧 CSS，而非新版统一样式，停止录音按钮被遮挡。现统一导入 `app.css`。
3. 当前 Android 共享界面检查发现桌面整合样式覆盖了和弦栏原有留白，恢复移动端的 4 px 上下内边距和 8 px 下间距。
4. `gh` 下载日志压缩包发生 EOF，改用 GitHub 连接器读取作业日志成功。两套工作流增加失败截图附件，便于下次直接定位。

5. 上传后的 Source checks 41640382447 暴露了真实小窗口问题：原型在 1180 px 以下把控制台改为绝对定位，遮住第 3、4 列和弦。正式桌面布局现保持侧栏占据独立列；交互检查固定在 1024 px 宽度复现并确认真实点击通过，不使用强制点击绕过。同期 Pages 41640382471 已通过。

## 验证与边界

本地确认类型 / 文案 / 桌面语法、材料审计和格式；复跑相关 CI UI、播放控件、和弦交互、网页演示与 Android 共享界面检查。只用隔离合成项目，网页演示麦克风调用为零；不重装模型、不重复分离推理、不操作作者的私人工程。远端最终状态以本次上传提交的 Actions 为准。

本轮上传源代码和文档，不制作新 Setup、不发布 Release。推送 main 后网页工作流会按仓库既有设置自动更新演示站点；下载仍指向现有正式发行版。
