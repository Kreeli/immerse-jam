# Android 本地设备验收

2026-10-30。此记录的设备操作仅在现有模拟器进行。用户随后明确要求停止追加检查，直接提交并发布；交付范围见 [0.1.9 发布说明](RELEASE-0.1.9.md)。

## 实际执行

使用 Android 15 x86_64 现有模拟器、约 2.4 GiB 内存，测试音频均为隔离生成的合成音乐。保留模拟器原有数据，没有使用电脑私人曲库。

- 原生 Beat This! final0：36 秒样例跨越 30 秒模型窗口，得到 72 个节拍、18 个小节首拍、120 BPM，与电脑结果的最大时间差为 0。默认分析保留导入的 120.123 BPM 和已校准标记；明确替换才重新识别。
- 原生 MIDI 对齐：12 个合成音符，输出 73 个单调同步点，可信度约 0.887。独立变速样例的同步点误差中位数为 0.05 秒。结果不代表复杂真人演奏、反复段或弱和声曲目的精度。
- 变速录音：0.5× / +12 半音录下的 880 Hz、2 秒音频，归一化为 440 Hz、1 秒；100 ms 延迟换算后起点为 3.96 秒。原始 FLOAT WAV 单独保留。
- 强制停止应用后恢复：1.5× / −5 半音录音恢复为 440 Hz、1.5 秒，起点为 2.03 秒。录音源是合成信号，未冒充实体 USB 效果器。
- 完整歌曲包从 Android 文件桥到隔离电脑实例，再由电脑返回 Android，节拍、小节首拍和完整 MIDI 对齐一致；Android 系统打开分享文件入口通过。此项通过调试连接转送数据，不等于真实 WebRTC 网络验收。
- 实际 HTTP 局域网双向收发通过，保留 72／18 个时间标记及对齐；取消被阻塞的请求后可重新连接。公网地址被拒绝。
- 相机窗口能打开并用返回取消。模拟器虚拟场景未完成二维码识别，不将其记为扫码识别通过；需在实体设备对准电脑二维码验证。粘贴配对地址的收发路径已实测。
- 412 dp 手机和 1707 dp 平板布局、播放／暂停、浏览不中断、控制台、录音保存和返回通过；平板中央波形约 1139 dp。根页面两次返回退出。暂停后音频上下文挂起。

## 修复与结构

电脑归档使用带数据描述符的流式 STORED ZIP。Android 原先按流读取时边界不兼容；现在使用中央目录解包，继续校验路径、条目、展开体积和 SHA-256，并在失败时回滚。修复 Android 可选数值缺省为 NaN 的问题，以及空分组数组的跨端兼容。

电脑局域网和连接码分享改为完整归档，保留分析、附件与录音。Android 收发使用独立线程和流式文件，支持取消、重新连接与临时文件清理；不占用录音追加线程。录音处理失败保留原始文件和恢复标记。

新增原生计算放在 `processing/`，局域网代码放在 `transfer/`，界面与桥接放在 `src/platform/android/`。Java 和共享 DSP 都有独立测试，原生依赖许可随包提供。

## 自动检查与边界

53 项 Node、16 项 Java 计算／校验测试通过。3 项 Android 设备测试在首次执行通过；最后重复运行时，归档测试命中了此前已重新分析的同源合成样例，导入按设计去重后读到 120 BPM，而断言期望初始的 120.123 BPM。测试已改为每次使用独立源编号，避免依赖已有数据；随后用户要求停止检查并直接发布，因此未再次执行该最终修订。共享手机／平板界面回归包含节拍保护、主动替换、任务取消、系统分享和局域网选择收发。

后台／锁屏原生播放服务、真实网络 WebRTC、相机识别、ARM64 长时间温度／性能和实体声卡接线仍需补齐或验收。移动端六轨及专用主奏／节奏、主唱／和声模型适配尚未完成；可导入电脑已算好的全部结果。输入和单次录音最多 44 分钟，播放解码仍受内存预算限制。
