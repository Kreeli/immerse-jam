# Android 节拍与分享迁移

2026-10-30。Windows 已由用户验收；本轮继续更新 Android 源码，未生成 APK／安装包或发布 Release。

## 节拍优先

- 移植电脑同一份 Beat This! final0 权重，转换为约 78 MiB 的 ONNX，计划随 Android 安装包提供。没有重新训练或量化；权重与 Slaney mel 矩阵均固定 SHA-256。
- 使用同样的 22.05 kHz、1024 点 Hann、441 hop、128 个 Slaney mel 频带，以及 30 秒模型窗口、6 帧边界和保留前一窗口的拼接规则。模型接受短片段，不把短歌曲强行补齐至 30 秒。
- 预处理使用有抗混叠滤波的降采样；BPM 来自多拍跨度，识别小节首拍后估计拍号。不使用轻量自相关算法代替正式手机节拍识别。没有检出节拍时保留空结果，用户可手动校准。
- 已有节拍默认保留，只更新和弦。导入的电脑节拍、朋友分享的节拍和手动校准结果不会自动被重新估计覆盖；重新识别需要明确勾选替换。
- 和弦使用轻量本机 chroma 与 Viterbi 平滑，可编辑。识别质量仍取决于曲目，不等同于经过人工校对的和弦谱。

## 跨设备和朋友分享

1. 电脑导出“完整歌曲项目” `.ijam`，传到手机后用 Immerse Jam 打开，或在应用内导入。
2. 手机设备互传页面支持选择多首歌曲，通过系统分享发送完整 `.ijam`。接收方可从文件管理器或其他应用的分享菜单用 Immerse Jam 打开。
3. 完整包包含原曲、分轨、节拍、小节首拍、和弦谱、附件及设置。手机直接使用原有时间位置，不必重新分离或分析。
4. Android 已接入共享 WebRTC 连接码与文件存储接口，双方仍各自选择发送与接收内容，接收后还需确认导入。每个片段有顺序／长度检查，整包校验 SHA-256。Android 原生链路尚待安装后的设备回归。

电脑互传改用二进制 IPC，保留旧 base64 调用兼容；Android 字符串桥仅在平台边界转换。当前尚未提供 Android 应用内相机扫码；桌面局域网网页、系统分享与连接码是不同入口。

## 其他改进

- Android 增加 WAV 混音导出和分轨 ZIP 分享源码。按轨音量、声像、选听、跟练回听模式与创作分组组合混音；分块使用共享 SoundTouch 做变速／移调，避免整首 PCM 常驻内存。原生导出与系统分享的设备验收待打包后进行。
- WAV 读取支持 PCM16／24／32、FLOAT、RF64 与有界采样缓存；导入增加存储与中断保护。关闭应用时释放新增文件句柄和导出会话。
- 仍限制输入和单次录音最长 44 分钟；节拍模型要求至少约 1.2 GiB 可用内存，低内存或过热时停止，原结果保留。保留已有节拍、只更新和弦可使用较低内存门槛。

## 本轮验证

- 模型输出：PyTorch 与 ONNX 在 1500、612、72 帧输入上的最大 logit 差约 `2.4e-5`。独立重复转换检查固定摘要。
- 合成音乐对照：36 秒、跨 30 秒拼接，Java 手机特征经过 ONNX 推理及手机节拍后处理，与电脑得到相同的 72 个节拍、18 个小节首拍；时间差为 0。Java 与 float32 FFT 单帧特征最大差约 `5.2e-4`。
- Java 计算与对照 9 项测试通过。对照测试使用开发机 CPU 推理环境，没有以此冒充 Android 真机运行结果。
- 50 项 Node 测试通过，新增离线 DSP 的变速／音高／双声道／损坏输入与二进制互传检查。手机／平板共享界面检查覆盖节拍保留、明确替换、取消任务和分享入口，不依赖 SDK 或模型，纳入 CI。
- `.ijam` 节拍、小节首拍及已校准标记往返断言已加入 Android 设备测试源码；本轮只编译，不生成 APK 执行。

复杂真实曲目、手机上的速度／温度、系统分享接收和原生 WebRTC／混音导出仍需后续设备验收。未完成能力继续见 [Android 功能表](ANDROID.md)。
