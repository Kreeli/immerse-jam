# Architecture / 开发结构

Platform boundaries: `desktop/` and `backend/` are Windows-only; `platforms/android/` owns the native Android host, storage, capture persistence and isolated inference service; `src/platform/android/` owns its browser bridge and responsive layout. Shared React features and Web Audio calculations remain in `src/`. Vite emits separate `dist/` and `dist-android/` builds. Android models have their own fixed catalog and supported tensor contracts; they do not reuse desktop checkpoints. See [Android coverage](ANDROID.md).

`src/app/App.tsx` composes views; `useWorkspace.ts` coordinates project selection, desktop events and playback. Features are split under `src/features/`: library, player, recording, chords, score, analysis, models, transfer, migration and settings. `src/shared/types.ts` defines the project contract.

The active audio project is independent from the browse route (`showPlayer`/`page`). Navigation hides the workspace view without unmounting its recording controls or unloading audio; one integrated transport remains visible. `PracticeHub` lists sessions, `SessionCreateDialog` collects creation options before the first write, and `desktop/sessions.cjs` copies source media transactionally. `playbackTracks` applies practice capture/review routing without mutating stored controls. Project deletion is a checked desktop operation that uses the Windows Recycle Bin.

`src/audio/Player.ts` owns the AudioContext, common source clock, mixing graph, SoundTouch DSP, metronome scheduling and cached waveforms. Reusable calculations live in `metronome.ts`, `performance.ts`, `envelope.ts` and `latency.ts`. `capture.ts` and its AudioWorklet collect timestamped stereo Float32 PCM with no software-monitor output. Peak scanning yields between slices without cloning complete PCM; mixed envelopes render one two-second buffer at a time through a shared queue. Decoded audio and peaks are reused when mounted takes change. Desktop playback checks actual source durations against available memory before decoding; Android has its own budget and 44-minute input cap.

One SoundTouch worklet lives for the player's lifetime. `playback-processor.js` extends the upstream processor with a render-clock FIFO reset for seeks, guarded by short output fades. Loop source segments are scheduled ahead on the AudioContext clock, with short edge fades; loop rollover does not pause transport or rebuild DSP. A serial cancels stale asynchronous resumes during rapid seeks. Workspace unmount and pagehide dispose the graph, worker and AudioContext; browse navigation keeps the workspace mounted. The Electron window disables background timer throttling so scheduling can continue while browsing or minimized.

Recording and backing share an AudioContext clock. Input frames map through speed and latency correction to the original song timeline; FFmpeg normalizes recorded speed/pitch while preserving raw input.

`CreationTracks` renders collapsible outer source groups and recording rows. `desktop/groups.cjs` owns checked copying, validation and export routing; `performance.ts` mirrors its playback policy with cross-module contract tests. Group waveform rendering covers only the group's local region, with a bounded mix cache; creation does not pre-render an unused full-project mix. `TrackWave` reuses decoded channels and waits for loading to finish. `LiveEnvelope` retains fixed 10 ms peak bins rather than PCM and sends only the visible window to the shared waveform canvas, preserving timing and envelope shape while recording. `PracticeWaves` aligns live/saved takes with the main mix. The recorder remains mounted beside Play in `Transport`; top quick actions and `SidePanel` keep marker lists from resizing the timeline.

`desktop/main.cjs` dispatches normal launch versus installation preparation. `locations.cjs` applies selected storage roots before creating a profile; `application.cjs` composes windows, permissions and services. `installation.cjs` validates independent writable directories, prepares dependencies/models and commits `installation.json` only on success. `installer/setup.nsh` adds storage/component pages and waits for preparation before Finish, with resumable retry. Existing installed-library data is copied without deleting the source; virtual environments are rebuilt at the new absolute path. Modules separate store, takes (`ipc/recordings.cjs`), archives, export, models/runtime/jobs, migration, LAN and WebRTC transfer. `locale.cjs` translates native dialogs; `transfer-page.cjs` provides the LAN page.

`folders.cjs` persists local category names and memberships atomically in `folders.json`, independently from media and playback. The sidebar, music cards, practice table and folder page share `FolderPicker`; deleting a category never deletes a project. Old named playlists migrate once. Windows launch sets the same AppUserModelID as installer shortcuts and supplies the icon/relaunch details.

`shared/ipc-methods.json` is the request allowlist. `prepare-preload.cjs` generates a static sandbox-compatible bridge. A contract test compares registered handlers against it. Calls are accepted only from the workspace window.

Python jobs run privately via `backend/worker.py`: JSON request, JSON progress/result output, diagnostic stderr. Separation, analysis, rhythm, alignment and validation have distinct modules. Validated results commit together; failure retains previous playable results. Vendor sources retain their own licenses.

`audio-tools.cjs` downloads pinned FFmpeg when needed. `runtime.cjs` prepares private Python; `models.cjs` validates model artifacts. No global Python/CUDA toolkit is required.

All built-in artifact files, including SCNet XL configuration, require pinned SHA-256. Custom weights/configurations are rehashed before use; `model_safety.py` forces restricted PyTorch loading and prechecks safe YAML in the worker process. UTF-8 streams use incremental decoding. Every LAN archive response owns a UUID-scoped temporary package cleaned after streaming. Stored playback values are normalized, and audio export independently rejects invalid tempo/pitch/volume before constructing filters.

Chinese messages map through `src/i18n/index.ts` and `shared/locales/en.json`. `preferences.ts` stores language/theme/accent outside projects. Native dialogs/LAN share the catalog; user text is not translated. Themes use CSS tokens, and canvas listens for appearance/language changes.

Use `npm ci`, `npm run check`, `npm test`, `npm run build`. `npm run format` maintains formatting. Backend tests need `npm run prepare:runtime` first. `npm run package` creates NSIS. CI excludes large model downloads. Playwright tests create isolated synthetic fixtures and run muted.

New installs read `installation.json` beside the executable: the selected data root holds `library/`, `runtime/`, `profile/`, logs and crashes. Legacy installs without this file retain their previous app user-data location; development uses `.runtime/`. `IMMERSE_DATA_DIR`, `IMMERSE_RUNTIME_DIR` and `IMMERSE_PROFILE_DIR` allow isolated workspaces; `IMMERSE_LOCALE` initializes test language. These overrides are unnecessary for normal installed use. Windows installer extraction can still use OS-managed temporary storage; large application dependencies and caches use the chosen root.
