# 0.1.8 源码审查与修复

2026-10-29。依据实际源码复现用户转述的问题，并用隔离合成音频验证。

| 反馈                               | 核对结论                                   | 修复                                                                                                                        |
| ---------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 循环、拖动重建 SoundTouch          | 属实，循环通过 seek 重启播放，存在间隙风险 | DSP 复用；循环源按音频时钟提前排程；seek 清空旧 FIFO，短淡入淡出；连续拖动取消旧的异步启动                                  |
| 录音权限失败清空循环               | 属实，保存循环发生在可能失败的异步步骤之后 | 开始时立即保存，任何失败恢复原循环                                                                                          |
| 速度 0／负数导致导出卡死           | 属实，atempo 的循环无法结束                | atempo 拒绝非正数／非有限数；导出入口独立验证；旧数据归一化                                                                 |
| SCNet XL 无 SHA-256 仍标记准备完成 | 属实                                       | 上游 v1.0.15 提供权重／配置摘要，缺摘要拒绝内置安装，下载通过后才写验证记录                                                 |
| 自定义 Torch pickle 可任意执行     | 不能由这次检查直接认定                     | 已有 SCNet 显式 weights_only=True，私有环境 Torch 2.8 默认限制；新增自定义模型运行时强制限制、YAML 安全检查和权重／配置复验 |
| dispose 无调用                     | 属实                                       | 组件清理和 pagehide 调用释放，浏览路由不触发释放                                                                            |
| 并发互传包损坏                     | 局域网同一首歌复用临时文件属实             | 每次下载独立 UUID 包，并在流完成／断开后清理；WebRTC 原本已有独立会话                                                       |
| 中文进度偶尔乱码                   | 分块独立转字符串可能切开 UTF-8 字符        | 子进程流使用增量 UTF-8 解码                                                                                                 |
| 缺省导出名中断整批                 | 属实，直接调用 replace                     | 安全默认名及序号，避免同名轨覆盖                                                                                            |

SCNet XL 摘要来自 [上游 v1.0.15 发布](https://github.com/ZFTurbo/Music-Source-Separation-Training/releases/tag/v1.0.15)。PyTorch 的默认行为与限制见 [序列化说明](https://docs.pytorch.org/docs/stable/notes/serialization.html#torch-load-with-weights-only-true)；哈希和 weights_only 均不能替代不可信模型的安全隔离。

界面同步调整：保留 Beat This! 原名；侧栏由上到下为本地引擎状态、用户反馈、请作者喝一瓶冰可乐；默认分类；跟练/创作列表不再称项目；音乐播放页右上角选择以当前歌曲创建跟练或创作；自制谱删除需确认，保留歌曲和其他谱。

验证命令与实际结果见 [验证记录](VALIDATION.md)。自动化音频测试用于捕获静音间隙和节点重建，实际效果器、驱动和主观听感仍需要设备试听。
