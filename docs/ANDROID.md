# Android 功能与预览历史

当前版本为 **0.1.0-preview.4**。当前构建步骤见 [Android 开发](../platforms/android/README.md)，桥接与音频协议见 [接口与契约](INTERFACES.md)，实机和公开发行状态见 [交接入口](../DEVELOPMENT_HANDOFF.md)。下方 2026-10-30 的模型、推理和内存说明属于早期试验。

## 最新：连续窗口与界面帧刷新

窗口预取仍保持有界，音频线程现在按共同采样时钟连续取样，不再每秒重启一次音源。波形使用局部帧刷新和缓存绘制；原生波形生成独立线程及 64 MiB 磁盘缓存。初始预热必要窗口即可播放，压缩格式首次仍可能等待磁盘解码。主页面约 10 Hz 更新，视觉波形/进度独立随屏幕帧刷新；这不是所有手机均能达到固定帧率的保证。

三条跟练波形自动分配高度，播放条分两排；和弦直接点格输入，列表内新建删除。输入时间戳增加预热，手机起音检测更敏感并抑制突发噪声。详细检查范围、内存边界及真机待验见 `docs/REVIEW-2026-11-01.md` 顶部。

## 最新交互与录音

顶栏为设备互传、导入/导出、帮助、设置；内容视图独占下一排。Radix UI 提供动画选择菜单和弹层，保留中英文、明暗与减少动态效果偏好。播放改六秒预读、三秒预排，过期读取可取消，进度条松手恢复；内存缓存上限仍为 48 MiB（不是总内存）。

录音与延迟测试共用 Android 原生 AudioRecord，输入来自 AudioManager 枚举，兼容双声道/单声道。仅前台录音，切后台原生端停止；保留已收到录音。Android 15 模拟器实际录制保存与取消后重开检查通过，实体麦克风/USB/蓝牙还需验收。细节与检查范围见 `docs/REVIEW-2026-11-01.md`。

## 最新播放方式

当前开发版已改为磁盘分块 PCM 播放，原来的“整曲解码最多 320 MiB”不再用于此播放路径。WAV / RF64 可直接随机读取；压缩格式第一次准备磁盘缓存后分块读取，保留原媒体。初次缓存仍可能耗时与占用存储，当前媒体最长 44 分钟的既有约束保留。浏览器音频窗口约一秒，缓存最多 48 MiB；该数字不是应用总内存。和弦页默认四列，编辑设置折叠。

详细验证边界见 `docs/REVIEW-2026-11-01.md` 顶部最新说明。

## 2026-11-01 新方向（本轮开发）

本轮将 Android 定位为外部音轨播放器、跟练和创作工具。入口收敛为导入、设备互传、新建创作；隐藏音乐库与模型管理，旧歌曲直接作为跟练打开。分轨、分析、自动对齐由电脑完成，手机仅保留导入数据、手工编辑、音轨叠加、录音及分轨/总混音导出。

构建不再需要 `android:models`，不打包模型和 ONNX。旧推理服务与模型引擎已移除，可在 Git 历史中查阅；桥接明确拒绝推理和模型下载。

后台使用媒体前台服务、MediaSession、音频焦点、CPU 唤醒锁及原生调度。正常速度和音调直接通过音频渲染线程，避免无必要的变速计算。暂停释放焦点与唤醒锁，电话、拔耳机与路由变化会暂停。应用被系统结束后停止播放。当前播放路径见上方的连续 PCM 窗口说明。

录音仅支持前台进行；切后台或音频焦点丢失时保存已收到部分。系统或厂商对 WebView 后台策略仍需 ARM64 真机验收，不能将编译成功等同于锁屏稳定性证明。

校准支持跟拍估计、剔除离群、波动提示、手动修正、录音与节拍的前后对比试听。它包含人的跟拍偏差，不是纯硬件回环测量。

以下内容是旧预览版实现和验收历史，不能作为本轮能力说明。

2026-10-30，`0.1.0-preview.1` 调试签名预览版，随 [0.1.9 Release](https://github.com/Kreeli/immerse-jam/releases/tag/v0.1.9) 提供。Android 9+、ARM64 手机／平板；本地验收使用 Android 15 x86_64 模拟器。用户在本地调试后明确要求停止追加检查并发布，尚无实体手机性能和声卡接线验收。

共享 `src/` 的音乐库、跟练／创作、波形、和弦编辑、乐谱和混音界面。`src/platform/android/` 负责桥接和移动布局，`platforms/android/` 负责原生系统功能；Windows 的 `desktop/`、`backend/` 和模型配置不混入 Android。两端使用同一 `.ijam` 数据结构。

## 性能保护

- 输入音频和单次录音最长 44 分钟。导入先检查媒体时长，实际解码与录音追加也检查帧数；时长不明的归档媒体需先转为可识别格式。44 分钟是时长上限，长曲多轨仍可能触发下述内存预算。
- 只启动一个分离任务，推理使用 `:inference` 独立进程，界面不加载 ONNX 模型。
- 运行前检查可用内存、低内存标记和存储空间；UVR 默认至少 900 MiB 可用，SCNet 至少 1200 MiB。内存估计是保守门槛，不是绝对防崩承诺。
- 固定片段、一次一个批次、最多两条计算线程；音频解码和输出写磁盘，内存不随整首歌曲线性增长。每块之间检查取消、过热与内存压力；单块超过 180 秒终止。
- 首块同时验证模型规格和有限输出。结果写入新目录，全首成功后提交；中途失败保留旧结果。后台完成的结果通过独立落盘记录在重开应用时补交。
- 播放也有独立解码预算：最多约 320 MiB，且不超过当前可用内存的四分之一。长曲多轨超过预算时会提示，后续需要原生流式播放进一步放宽限制。
- 暂停后挂起 AudioContext；录音和校准会话保持运行，结束后释放。模型推理服务停止后取消绑定，避免持续保留高优先级进程。
- MIDI 对齐最多保留 200 万个回溯单元，成本矩阵只保留三行；音符转特征采用范围累加，避免密集长音符导致二次计算量。

## 局域网传输

电脑在设备互传中选择歌曲并生成配对二维码，手机扫描或粘贴地址，再选择接收。手机也能把上方选中的内容发回电脑，由电脑确认导入。原曲、各模型分轨、节拍、乐谱对齐、附件和录音随完整包保留；已有同源内容不会被静默覆盖。

原生局域网客户端只接受带临时令牌的私有 IPv4 HTTP 地址，不解析域名、不跟随重定向。Android 允许此本机网络 HTTP 用途；网页本身仍限制为应用资源来源并禁止混合内容，模型下载仍为固定 HTTPS 来源与摘要校验。无需云端存储或自建服务器。

- Java 单元测试：6144 点混合基数 FFT 往返，以及频谱／波形恢复长度和误差通过。
- Android 设备测试：`.ijam` 字节往返、路径范围、独立跟练，以及中断录音恢复通过。
- 412 dp 手机：菜单、设置说明、返回上一级、播放、浏览不中断和隐藏式控制台通过；无横向页面溢出。
- 1707 dp 平板：常驻导航和混音面板，中央波形约 1139 dp；两次返回退出通过。
- 12 秒合成输入实际完成 UVR 两轨及 SCNet 四轨分离，保留旧结果。两者均是 CPU 模拟器兼容性验收，不代表实体手机速度、音质评分或长时间热稳定性。
