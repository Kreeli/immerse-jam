# Android 平板连续音频检查（2026-11-01）

用户明确授权通过无线 ADB 检查其平板，并覆盖安装同签名调试版；保留原曲库和媒体，仅通过正常播放/暂停/跳转操作测试。没有修改媒体内容或发布 Release。

设备报告型号 PA2511，SoC SM4450，Android 15，WebView 154.0.8037.106。样例为用户原有的六轨工程，时长 263.84 秒，原速、原调。以下数据不包含用户歌曲名称、工程编号或无线配对信息。

## 持续播放的主要发现

不是必须将整曲装入内存。4 ms 的 `interactive` 输出预算在该平板的 WebView 六轨图上反复欠载，调整磁盘读取本身不能消除它。测量用真实音频图的 `AudioContext.playbackStats`，选取相同歌曲约 85 秒处，预热 2.5 秒后比较约 20 秒的统计增量。

| 策略                                   | 实际基础缓冲 | 测量区间 | 欠载次数 | 欠载总时长 |
| -------------------------------------- | -----------: | -------: | -------: | ---------: |
| 原实时输出策略（已包含第一轮取数优化） |         4 ms | 20.412 s |       85 |     340 ms |
| 20 ms 请求                             |    21.333 ms | 19.067 s |        1 |  21.333 ms |
| 40 ms 请求初次比较                     |        40 ms | 20.038 s |        0 |       0 ms |
| 最终安装包复核，含所有权转移           |        40 ms | 20.075 s |        0 |       0 ms |

这不是麦克风对扬声器回录，也不是所有歌曲、任意后台负载或所有外接设备都无中断的证明。初次初始化/预热期间仍记录过输出欠载；表格不将它们混进稳定播放区间或隐去为“全程零事件”。用户实际试听仍是验收依据。

## 实现

- Android 固定请求约 40 ms 输出缓冲，桌面保持原来的 interactive。它提高实时渲染容错，代价是更多输出延迟；本机最终测试瞬时 `outputLatency` 约 104–112 ms，不能把应用内恢复测量当作实际耳朵听见的总延迟。录音前需重新校准。
- 磁盘仍按有界窗口随机读取，初始/跳转先准备约 200 ms 必要片段，并在拖动过程中提前读取；完整一秒窗口在后续填充。
- 原始交错 Float32 PCM 直接移交给音频线程；去掉 AudioBuffer、分离左右声道和复制两份数组的过程。窗口缓存由各轨音频线程持有，范围仍按轨数/倍速受限，页面不再保留第二份完整 PCM。
- 音频处理按连续块快速处理，大多数块只计算一次时钟、窗口和边界；窗口接缝仍连续插值。关闭的旧处理器明确结束，避免切工程后继续占资源。
- WAV 读缓存含一个插值保护帧，避免跨页反复换页；48 kHz 直接取样，其他采样率共用立体声插值坐标。
- 拖动/内部跳转和速度变化期间保留音频焦点，减少重新启动输出链；真正暂停、切项目、离开播放器仍按原逻辑释放。
- 倍速弹层增加滑条上方当前倍速数值，“重置”固定为横排按钮。

## 其余检查

原安装包拖动恢复的三次应用内监测值为 257–272 ms（音频线程探针，另有输出设备延迟）；第一轮低缓冲取数优化为 22–45 ms。最终 40 ms 缓冲版本两次应用内分析节点监测约为 68/72 ms，监测方式不同，不作为严格的同口径倍数结论。实际声音还需经过输出设备缓冲。

五项音频生命周期/连续采样检查通过，覆盖原始交错 PCM、非整数录音偏移、短片段跨秒边界、取消授权、并发读取上限和安静起音检测。1,000,000,044 字节合成 WAV 的有界随机读取检查通过（Java 32 MiB 堆，仅证明读取器）。共享界面检查通过，0.8 倍速/+2 半音下阻塞界面 1.2 秒无检测到音频空洞，跳入静音段恢复无残留。TypeScript/960 条文本/桌面语法、ARM64 与 x86_64 debug 构建通过。

真实平板截图使用 ADB 原生截屏；此设备的 DevTools 网页截图会漏掉 GPU 波形层，不可将其误判为波形为空。倍速数值和横向重置已在原生截屏确认。最终测试后应用停在曲首且暂停，曲库和媒体保留。
