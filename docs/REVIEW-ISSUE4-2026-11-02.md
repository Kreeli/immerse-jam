# Issue #4 修订与验收 · 2026-11-02

本轮根据用户与 issue #4 的实测反馈修改。维持现有页面结构，先修安装与数据保护，再补局部布局、波形和检查更新。未获本轮 Release 授权，不发布、不替换公开附件、不关闭 issue 或发评论。

## 后续修正：安装向导直接显示下载进度

用户随后反馈看不到下载栏。先前进度是独立窗口，NSIS 仍停留在复制进度；而数据 / 模型页使用的坐标又超出标准内容区，底部选项可能被裁掉。现在把下载作为复制文件后的独立 NSIS 页面，保持同一个窗口：先选模型，随后显示所选清单、当前步骤、文件名、已收 / 总大小、速度、文件百分比。未知大小依赖及校验使用活动条，已下载内容可复用 / 续传，失败可在原页重试。准备程序成功退出后才解锁下一步；完成页不允许返回而重复准备。静默安装保留原流程。

针对性验收使用正式选择 / 下载页面和实际本机 HTTP 小文件，去掉注册表提交，不安装私人程序、不重下 Python / PyTorch。六个模型选项完整显示，选择可传入准备程序，真实字节与进度栏一致，完成后两条进度均到 100% 并解锁下一步，再正常进入完成页。状态文件的零进度、中文、步骤保留、校验清空旧百分比、错误与成功提交，以及安装 / 同目录升级有关检查共五项通过。完整 NSIS 编译通过，交付文件仍为下方同名 Setup；本轮没有新增 Android 包。

## 上一次安装优化为何没有解决问题

直接检查已发布 v0.1.10 对应的 `release/install-repair/win-unpacked/resources/app.asar`，而非仅看当前源码，确认五个遗漏：

- 文件下载仍是 Node fetch，未接入系统代理。
- PyTorch 的大包仅走官方索引。
- PyPI 选择只读取首块，不比较大文件吞吐。
- 冷启动 import 超时为 30 秒。
- 检查失败的 Promise 也缓存五分钟。

上轮主要完成安装迁移故障、进度窗口及 uv / Beat This! 内置资源，所以能修复作者本机的特定失败，却不能证明陌生机器、国内网络下的首次安装已顺畅。相关审计结果保存在被忽略的 `.runtime/issue4-published-package-audit.json`。
